# MIDI 演奏与九音手碟

应用直接读取原始 `.mid` / `.midi`，默认与 `scripts/midi2score.py` 共用自动识调和音级折叠算法；所有音高都会落到手碟九键，保留和弦及全部起音。无需先转 TXT，旧 `data/scores/*.txt` 仍可播放。

## 使用流程

1. 连接 ATmega32U4 板。v2 固件可同时演奏和弦；旧单键固件也可演奏 MIDI，会自动把和弦按顺序敲出。
2. 打开「自动演奏」，用「导入 MIDI」选择文件，或拖入多个 MIDI。每个文件单独报告结果；相同内容重复导入不会复制新歌。
3. 选曲查看音轨。默认与原脚本一样选全部非鼓音；可只选旋律和需要的伴奏。所选音轨为空时自动使用文件中的可用音符继续演奏。
4. 默认「自动识调 + 音级折叠」，与原脚本 `--root auto --strategy degree` 一致，可调整移调、映射策略、主调、速度和开头空白。
5. 直接点击播放即可，设置自动保存；也可手动「保存并重新分析」。不会因音域、重击或设备容量问题禁用播放，所有音符自动适配。
6. 点「播放选中曲目」，连接就绪后有 3 秒倒计时切到游戏。主窗及悬浮窗提供暂停、继续、停止、上一曲、下一曲和五种模式。

曲库选择与实际播放分别显示：浏览另一首歌只切换详情；点击播放或上一曲/下一曲才切歌。设置修改在下次开始该曲时生效。

## 删除曲目

每首歌右侧可点击「删除」，再点「确认删除」。导入的 MIDI 和原有 TXT 都可以移除；删除当前演奏的曲目会先停止该曲，停止失败时保留曲目并提示原因。删除其他曲目不打断正在进行的演奏。

删除选中曲后自动选中相邻曲，删空曲库后仍可继续导入。用于导入的电脑原始 MIDI 文件保留，曲库副本及逐曲设置移入 `data/music/trash/<标识>/`，不再参与曲库扫描。该目录的 `song.json` 记录原曲名，`original.mid` / `original.midi` / `original.txt` 保存文件；需要恢复时可重新导入 MIDI，或将 TXT 复制回 `data/scores/`。删除失败会回滚文件移动与索引变更，可重试。

## 乐器与音高映射

当前九音手碟持续按住只触发一次，声音自然衰减。每个起音触发 **50ms 短按**，MIDI note-off 和踏板不延长按键。解析保留音符起止、力度、通道和轨道，踏板、弯音、触后的不可表达部分会提示，原文件完整保存。

下表沿用项目已有的 C 调相对音高假设，不代表对游戏实际频率做过测量。通过移调可调整 MIDI 与游戏的对应关系。

默认先按旧转换器的最高音直方图识别原曲大调，再以音级优先、绝对音高距离打破平局的规则映射到下表。与旧脚本不同的是保留全部和弦，不执行 `top` 单音折叠或 `min_gap=100` 丢音。每个起点间隔按旧脚本逐段四舍五入到毫秒。Lemon 的 573 条按键与停顿、241693ms 总时长与现有 TXT 全部一致。

| mask 位 | 按键 | 原简谱 | MIDI 音高 |
|---|---|---|---|
| 0 | B | L6 | 57 / A3 |
| 1 | F | M3 | 64 / E4 |
| 2 | G | M4 | 65 / F4 |
| 3 | H | M5 | 67 / G4 |
| 4 | J | M6 | 69 / A4 |
| 5 | K | M7 | 71 / B4 |
| 6 | T | H1 | 72 / C5 |
| 7 | Y | H2 | 74 / D5 |
| 8 | U | H3 | 76 / E5 |

同刻不同键合并成完整状态 mask，一次 HID 报告发送。默认固件支持九键同时按下；可编译为最多六键的兼容模式，能力握手告诉后端实际容量。协议见 [PROTOCOL.md](PROTOCOL.md)。

## 适配设置

| 字段 | 默认 | 语义 |
|---|---|---|
| `selected_tracks` | `null` | 全部非鼓音轨；空选或无可用音符时自动回退到文件中的可用音符 |
| `transpose` | `0` | -36～36 半音，在映射前应用 |
| `range_policy` | `degree` | 与旧脚本一致的 `degree` 音级折叠 / `nearest` 转调后就近 / `smooth` 全音内平滑映射 |
| `root` | `null` | 自动识调；0～11 手动指定 C～B |
| `conflict_policy` | `adapt` | 全部音符自动分次或顺延；兼容接收旧 strict/skip 值并按 adapt 处理 |
| `mapping_version` | `2` | 旧设置首次加载时自动采用修正后的默认映射，保留选轨、速度等设置，无需重新导入 |
| `speed` | `1` | 0.25～2 倍，缩放时间轴，短按仍为 50ms |
| `skip_leading_silence` | `true` | 裁掉所选音轨第一个起音前的空白 |

同刻多个原音映射成同键时分次敲出。密集重击保证 50ms 按下和 10ms 松开，必要时顺延后续时间；超设备容量的和弦分批演奏。分析报告保留源音符数量与实际起音数量，两者相同，skipped_notes 为 0。设备容量包含短按期间重叠的按键。

支持 MIDI type 0 / 1 的 PPQ 时间轴，包括 tick 0 速度、跨轨和弦、变速、零力度 note-on、重叠同音。type 2 和 SMPTE 时间轴明确报错。单文件上限 16MB，事件上限 500000。格式说明依据 [Mido MIDI 文件文档](https://mido.readthedocs.io/en/stable/files/midi.html)。

## 调度与设备生命周期

- 使用单调时钟绝对时间，发送耗时不会逐音累加到后续节拍。
- 实际按下后至少保留 50ms，同键重击至少松开 10ms。系统卡顿时重新对齐时钟，继续演奏全部待播放音符。
- 暂停冻结位置并结束设备会话，释放按键；继续创建新会话，不重新触发暂停前已敲响的音。
- 停止、切歌、失败和自然结束均清理会话。generation 使旧任务失效，session 和序号使旧串口状态失效。
- 演奏期间（包括暂停）独占设备；监控、丢球、手动按键不能插入。停止或结束释放所有权，串口保持连接。
- 老固件的 MIDI 和 TXT 都使用单键命令，和弦顺序敲出。老固件缺少立即全释放命令，已有短按按原定时结束。
- v2 固件有会话超时保护，后端定期心跳；真实设备掉线与通信失败会展示错误，音乐适配和调度落后不拒播。

## 文件与模块

| 路径 | 职责 |
|---|---|
| `backend/music/midi_reader.py` | 原始 MIDI → 带轨道和通道的音符时间轴 |
| `backend/music/compiler.py` | 选轨、移调、音域适配、冲突分析 → 完整键状态事件 |
| `loco_box/handpan.py` | 转谱脚本与直接演奏共用的自动识调及三种音高映射 |
| `backend/music/scheduler.py` | 可暂停的单调时间轴 |
| `backend/music/library.py` | 原文件、哈希标识、设置、解析与编译缓存 |
| `backend/music/legacy.py` | 旧 TXT 适配 |
| `backend/features/music.py` | 播放器状态、模式、调度与设备会话 |
| `backend/api/music.py` | 曲库、导入、设置与播放 API |
| `frontend/src/composables/useMusicPlayer.ts` | 主窗/悬浮窗共用控制与状态同步 |
| `data/music/originals/` | 原文件字节，按 SHA-256 标识保存 |
| `data/music/index.json` | 显示名与元数据 |
| `data/music/settings/` | 每首歌的设置 |
| `data/music/trash/` | 已删除曲目的本地备份，不参与曲库扫描 |
| `data/scores/` | 原有 TXT 曲库，刷新时兼容读取 |

曲库延迟加载，状态轮询不重复解析 MIDI。原文件按内容去重，显示名不作为磁盘路径。配置更新合并已有字段并原子替换文件。运行数据和个人 MIDI 文件不加入版本控制。

## 旧 TXT 格式

UTF-8，一行 `按键 停顿毫秒`，也接受逗号、冒号、等号分隔；空行及 `#` 注释忽略，非法键忽略，停顿缺省为 0。例如 `T 500` 仍表示按住 50ms 后停顿 500ms，下一次起音在 550ms 后；它不同于 MIDI 的绝对起音时间。

## 播放模式

| 值 | 自然结束后 |
|---|---|
| `sequential` | 下一首，到列表尾停止 |
| `single` | 停止 |
| `repeat_one` | 重播当前曲 |
| `repeat_all` | 下一首，尾曲回到首曲 |
| `shuffle` | 随机另一首，仅一首则重播 |

上一曲按列表回退并环绕；下一曲按列表前进并环绕，随机模式下随机选择。每首开始前保留倒计时。模式和选中曲保存在 `settings.json` 的 `features.music` 中。
